01 / GUIA RÁPIDO

Instale pelo npm e gere a documentação

Tenha Node.js 24 ou superior. Entre na pasta do projeto que receberá os documentos; a CLI não cria uma pasta nova.

Revisar sem escrever arquivos
npx project-spec-starter@1.0.0 init --dry-run
Responder e gerar os arquivos
npx project-spec-starter@1.0.0 init

O npx executa o pacote do npm sem instalação global. O primeiro comando mostra apenas o plano. O segundo faz a entrevista, apresenta o plano e pede confirmação antes de escrever.

Instalação global, se preferir

Instalar a versão 1.0.0
npm install --global project-spec-starter@1.0.0

Depois, execute project-spec-starter init dentro da pasta do projeto. A instalação, sozinha, não gera documentos.

O que será criado?

O perfil padrão prepara documentos como PROJECT.md, docs/BUSINESS_RULES.md e docs/GITFLOW.md. AGENTS.md aparece quando você habilita agentes; .nvmrc aparece quando escolhe Node.js. O plano mostra a lista exata para suas respostas.

Arquivos existentes são preservados. Se houver conflito, a geração é bloqueada para você revisar o destino.

02 / ENTREVISTA

O que significa cada pergunta?

A entrevista mostra apenas as perguntas aplicáveis. Você pode registrar um objetivo ou caminho como pendente quando ainda não decidiu.

Projeto

Qual é o nome do projeto?
Nome usado nos documentos, como Portal de clientes. Não precisa ser o nome de um pacote npm.
Como você resume o objetivo inicial do projeto?
Descreva o problema e o resultado esperado em uma ou duas frases. Você pode deixar essa decisão pendente.
Como o projeto será organizado?
Escolha Aplicação única para uma aplicação ou pacote; Monorepo para várias unidades no mesmo repositório.

Unidades de monorepo

Quais unidades fazem parte do monorepo?

Uma unidade é cada aplicação ou pacote, como apps/web, apps/api ou packages/ui. A quantidade indica quantas você quer descrever agora, não quantas pastas serão criadas. O mínimo é uma.

Qual é o nome da unidade?
Um identificador para os documentos, como Web ou API.
Qual será o caminho da unidade?
O caminho relativo planejado, como apps/api. Pode ficar pendente; a CLI não cria esse diretório.
Qual é a natureza da unidade?
Seu papel: frontend, backend, full-stack, biblioteca, CLI, worker, infraestrutura, mobile ou outro.
Como você descreve esse outro tipo de unidade?
Só aparece quando escolhe Outro. Descreva o tipo com suas palavras.
Quais capacidades essa unidade possui?
Escolha o que ela faz, como interface web, API HTTP ou tarefas agendadas. É possível informar uma capacidade própria.

Conjunto do projeto

Qual é a natureza principal do projeto?
O tipo do conjunto. Em um monorepo com site e API, pode ser Full-stack; cada unidade mantém seu tipo.
Como você descreve esse outro tipo de projeto?
Só aparece quando escolhe Outro. Escreva uma descrição curta.
Quais capacidades o projeto precisa ter inicialmente?
Marque características do conjunto, como interface web, API HTTP, persistência ou autenticação. Isso não instala frameworks.
O projeto usará agentes de desenvolvimento?
Responda sim se agentes de código participarão. O perfil padrão incluirá AGENTS.md; não é preciso escolher um fornecedor.

Runtime e padrão

O projeto usa Node.js?
Refere-se ao projeto gerado. A CLI usa Node.js, mas seu projeto pode usar outro runtime.
Qual versão do Node.js o projeto deve usar?
Aparece após responder sim. O padrão sugere 24 e gera .nvmrc com a versão escolhida.
Qual padrão de engenharia deve orientar o projeto?
Use o padrão recomendado e editável, registre que fornecerá um padrão próprio ou escolha não gerar um padrão inicial.

03 / PERSONALIZAÇÃO

Adapte sem perder o controle

A entrevista ou um JSON versionado podem fornecer as mesmas decisões. Em JSON, informe --dry-run para revisar ou --yes para gerar sem perguntas.

Revisar respostas em JSON
npx project-spec-starter@1.0.0 init --answers answers.json --dry-run
Gerar com respostas em JSON
npx project-spec-starter@1.0.0 init --answers answers.json --yes

O arquivo answers.json deve existir. O schema inicial é 1. Não inclua senhas, tokens nem URLs privadas nele.

Perfis e sobrescritas

Use --profile caminho/profile.json para escolher um perfil local. Use --overrides caminho/pasta para substituir apenas recursos específicos. As camadas são lidas nesta ordem: sobrescritas locais, perfil selecionado e perfil padrão. Nenhuma delas executa scripts locais.

Depois da geração, edite os documentos diretamente. Eles passam a ser a fonte de verdade e a CLI não os mescla nem sobrescreve em outra execução.

04 / EVOLUÇÃO

O que já existe e o que vem depois

A versão 1.0.0 entrega o bootstrap documental: entrevista condicional, respostas JSON versionadas, plano de geração, --dry-run, perfis locais e escrita que preserva arquivos existentes.

Geradores de código, receitas de componentes ou serviços e integrações opcionais com Skills estão planejados para marcos futuros. Eles ainda não fazem parte desta versão.

Para acompanhar decisões técnicas e contribuir, consulte o repositório no GitHub ↗.
